# 🎬 管理员登录全流程·终极版

这是一个宿舍报修系统，就像一个繁忙的小区，每个角色都有自己的职责：

## 📋 角色对照表

| 角色 | 对应代码文件/模块 | 核心职责 |
| :--- | :--- | :--- |
| **登录页面** | `src/views/Auth/LoginView.vue` | 收集用户输入，发起登录指令 |
| **大管家** | `src/stores/user.js` | 统筹全局，管理状态（Pinia）和持久化（Storage） |
| **小弟** | `src/api/auth.js` | 纯粹的通信兵，负责发送 HTTP 请求 |
| **安检员 A** | `src/utils/axios.js` (请求拦截器) | 发送前自动添加 Token |
| **中转站** | `vite.config.js` (Proxy) | 解决跨域，转发请求给后端 |
| **安检员 B** | `src/utils/axios.js` (响应拦截器) | 统一处理错误，提取业务数据 |
| **保安** | `src/router/index.js` (守卫) | 根据 Token 和 Role 决定谁能进哪个房间 |

## 🎬 第一幕：发起请求

1. **登录页面 (LoginView)** 对 **大管家 (user.js)** 说："我要用账号 `admin` 和密码 `123456` 登录！"
2. **大管家 (user.js)** 接下单子，转头对 **小弟 (auth.js)** 说："去，把这个账号密码打包好，发给后端。"

## 🚚 第二幕：出发前的安检（请求拦截器）

3. **小弟 (auth.js)** 拿着包裹准备出门，在门口遇到了 **安检员 A (axios 请求拦截器)**。
   * **安检员 A** 检查包裹："你有通行证（Token）吗？"
   * **小弟** 说："我是去登录的，还没拿到通行证呢。"
   * **安检员 A** 说："行吧，那我不给你贴标签了，直接放行。"
   * *(注：如果是已登录状态下访问其他接口，安检员 A 会把 Token 贴在包裹头上)*

## 🌐 第三幕：跨越边界（Vite 代理与后端）

4. **小弟** 跑到小区门口（浏览器），把包裹交给 **中转站 (Vite 代理)**。
5. **中转站** 看到地址是 `/api` 开头，直接把包裹转交给了 **后端服务器**。
6. **后端服务器** 拆开包裹，核对账号密码。核对无误后，生成了一张 **VIP 通行证 (Token)** 和一张 **身份卡 (User Info)**，装进一个新包裹寄回。

## 🛡️ 第四幕：回家后的检查（响应拦截器）

7. 包裹回到前端，先经过 **安检员 B (axios 响应拦截器)**。
   * **安检员 B** 检查包裹上的封条（HTTP 状态码）和业务印章（code: 200）。
   * **安检员 B** 确认："一切正常，没有报错。" 于是把包裹里的核心内容（JSON 数据）取出来，递给 **小弟**。
   * *(注：如果后端返回 code: 500，安检员 B 会直接拉响警报 ElMessage.error，并把包裹扔掉)*

## 🏠 第五幕：入库归档（Pinia Store）

8. **小弟 (auth.js)** 把核心数据交给 **大管家 (user.js)**。
9. **大管家** 开始忙碌地归档：
   * 把 **VIP 通行证** 和 **身份卡** 放进 **保险柜 (Pinia State)** —— *为了让全屋的人（组件）都能立刻看到你是谁。*
   * 把同样的东西抄写一份，记在 **记事本 (SessionStorage)** 上 —— *为了防止你突然失忆（刷新页面）。*
10. **大管家** 对 **登录页面** 喊话："搞定啦！你现在是管理员了！"

## 🚪 第六幕：门禁核查（路由守卫）

11. **登录页面** 收到信号，试图推开 **管理员大厅 (/admin)** 的大门。
12. 门口的 **保安 (router.beforeEach)** 拦住了它：
    * **保安** 问："你有通行证吗？你是管理员吗？"
    * **登录页面** 出示 **记事本 (SessionStorage)** 上的记录。
    * **保安** 看了看："嗯，Role 是 3，匹配！请进。"
    * *(注：如果此时一个学生想闯进管理员大厅，保安会发现 Role 不匹配，直接把他踢回学生首页)*

## 🎉 第七幕：正式上岗

13. 大门打开，**管理员布局 (AdminLayout)** 和 **首页 (AdminHomeView)** 加载出来。
14. **Header 组件** 从 **保险柜 (Pinia)** 里拿出身份卡，显示："你好，超级管理员"。

# 📡 WebSocket 实时通信全流程

## 🏠 故事背景

登录成功后，小区里的居民（用户）需要能实时收到通知和聊天消息，这就需要一套实时通信系统，像小区里的对讲机一样，随时保持联系。

## 📋 角色对照表

| 角色 | 对应代码文件/模块 | 核心职责 |
| :--- | :--- | :--- |
| **小区总机** | `src/components/Layout/StudentLayout.vue` | 发起连接请求，启动通信系统 |
| **通信顾问** | `src/composables/useWebSocket.js` | 管理连接生命周期，处理业务消息 |
| **接线员** | `src/utils/websocket.js` | 底层连接管理，收发原始消息 |
| **广播员** | `src/utils/eventBus.js` | 消息中转站，广播给所有订阅者 |
| **聊天室** | `src/views/Student/ChatView.vue` | 展示聊天界面，发送和接收消息 |
| **后端服务器** | WebSocket Server | 转发消息，管理在线状态 |

---

## 🎬 第一幕：建立专线（连接初始化）

1. **小区总机 (StudentLayout)** 对 **通信顾问 (useWebSocket)** 说："我们需要一条实时通信专线！"
2. **通信顾问** 查看记事本（SessionStorage）："好的，当前用户ID是 1，我来安排。"
3. **通信顾问** 对 **接线员 (websocket.js)** 说："请帮我建立一条到 `ws://localhost:8080/ws/1` 的专线。"
4. **接线员** 拿起电话（创建 WebSocket 对象），拨通了后端服务器。
5. 服务器回应："专线已接通！" (`ws.onopen`)

---

## 📡 第二幕：接收消息（实时推送）

6. **后端服务器** 收到一条给用户 1 的消息："你的报修单已被接单。"
7. **服务器** 通过专线发送消息给 **接线员**。
8. **接线员** 收到消息，打开信封（JSON.parse），发现是系统通知（type=1）。
9. **接线员** 对 **通信顾问** 说："有你的信！"（调用 messageCallback）
10. **通信顾问** 看了看信的类型，对 **广播员 (eventBus)** 说：
    * "大家注意！有新消息！" (`emit('message_received', message)`)
    * "通知栏刷新一下！" (`emit('notification_updated')`)
11. **广播员** 拿起喇叭，向整个小区广播这两个消息。

---

## 💬 第三幕：聊天室响应

12. **聊天室 (ChatView)** 正在收听广播，听到 `message_received` 后：
    * "让我看看是不是我的消息..."（验证会话）
    * "是的！是我的聊天消息！"（type=2 且 relatedUserId 匹配）
    * "刷新聊天记录！"（调用 loadMessages）
13. **聊天室** 通过 HTTP API（小弟）去后端取最新消息列表。
14. 新消息显示在聊天界面上，用户看到了对方发来的消息。

---

## 📤 第四幕：发送消息

15. 用户在 **聊天室** 输入框中打字："太好了，谢谢！"
16. **聊天室** 点击发送按钮，对 **小弟 (api/notification.js)** 说："帮我把这条消息发给用户 2。"
17. **小弟** 通过 HTTP POST 把消息送到后端。
18. **后端服务器** 保存消息后，通过专线推送给用户 2。
19. 用户 2 的 **接线员** 收到消息，重复第二幕的流程...

---

## 🔌 第五幕：断线重连

20. 突然网络闪断，**接线员** 的电话断了（`ws.onclose`）。
21. **接线员** 不慌不忙："别急，我 5 秒后重新拨号。"
22. 5 秒后，**接线员** 重新拨通电话，专线再次接通。
23. 期间的消息不会丢失，因为后端已经保存，重新连接后会自动同步。

---

## 🚪 第六幕：断开连接

24. 用户离开页面，**小区总机** 要关闭了。
25. **通信顾问** 收到通知（`onUnmounted`），对 **接线员** 说："专线可以断开了。"
26. **接线员** 挂断电话（`closeWebSocket`），释放资源。

---

## 📝 学习笔记

实时通信就像小区里的对讲机系统，每个人都能随时收到通知：

### 🔑 关键知识点

1. **WebSocket**：持久化的双向通信通道，比 HTTP 更适合实时场景
2. **事件总线 (EventBus)**：组件间的消息中转站，实现解耦通信
3. **组合式函数 (Composable)**：封装可复用的业务逻辑
4. **自动重连**：网络异常时自动恢复连接
5. **事件订阅/取消**：避免内存泄漏，组件销毁时取消订阅
